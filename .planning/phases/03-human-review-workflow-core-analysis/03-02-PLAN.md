**Constraining decisions:**
- Relationship is inside `evidence_json`, not a column. Filter it with `json_extract`.
- Confidence bands are display thresholds only: strong `>= 0.90`, likely `0.75–0.89`, uncertain `0.50–0.74`, weak `< 0.50`.
- Source system lives on `source_component` / `source_assembly` / `source_supplier`, not on the reconciliation row. Join it.
- Phase 2 identity rows are PENDING at 0.95 (strong). Functional similarity is PENDING at 0.50 (uncertain). Variant-specific is PENDING at 0.95 with `review_needed` false.
</context>

<feature>
  <name>Filterable reconciliation queue</name>
  <files>app/services/review.py, tests/test_review.py</files>
  <behavior>
    `list_reconciliations(conn, entity_type, status=None, confidence_band=None, method=None, source_system=None, relationship=None)` returns `{"rows": [...], "count": N}`.

    Each row includes: reconciliation id, source id, source_system, source_reference, normalized_reference, status, method, confidence, relationship (from evidence), review_needed (from evidence, default None), rationale, canonical id.

    Cases:
    - entity_type `component` returns only component rows; `assembly` and `supplier` use their own tables. Unknown entity_type raises ValueError.
    - status `PENDING` excludes ACCEPTED and REJECTED.
    - confidence_band `uncertain` returns 0.50 and excludes 0.95. `strong` returns 0.95 and excludes 0.50. Bands are inclusive on the stated edges. Unknown band raises ValueError.
    - method `STRUCTURED` excludes `NORMALIZED` and `EXACT`.
    - source_system `PLM` excludes ERP rows. Match the value stored on the source entity.
    - relationship `functional_similarity` excludes `identity` and `variant_specific`.
    - combined filters AND together. `count` equals `len(rows)`.
    - empty match returns `{"rows": [], "count": 0}`.
    - results are ordered by confidence descending, then reconciliation id ascending.

    Do not change decision semantics from 03-01. Do not add CLI in this plan.
  </behavior>
  <implementation>
    Extend `app/services/review.py`. Query the entity table joined to its source table. Parse relationship with SQLite `json_extract(evidence_json, '$.relationship')` and `$.review_needed`. Keep confidence-band bounds in one dict in this module so later reports can import them.

    Tests insert source entities and reconciliation rows directly. Do not depend on the full CSV ingest.
  </implementation>
</feature>
