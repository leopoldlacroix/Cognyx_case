<feature>
  <name>Blockers, data-quality issues, and CLI reports</name>
  <files>app/services/quality.py, app/services/ingestion.py, app/db/schema.py, app/backend/cli.py, tests/test_quality.py</files>
  <behavior>
    `extract_voltage_facts(text)` returns the sorted unique set of voltages normalized to `"{n} V DC"` for integers found by `(?i)(\d+)\s*V`. `"48V DC"` and `"24 V"` become `{"48 V DC", "24 V DC"}`. Empty text returns an empty set. `"24V"` and `"24 V DC"` are one value.

    `blockers(conn)` writes `technical_fact` rows and returns a list of dicts: `issue_type`, `entity_ref`, `attribute`, `values` (sorted), `sources` (source_type, source_id, value), `explanation`.

    Cases:
    - Note text for object `CTRL-AIR-01` equal to the N-064 sentence (both 48V and 24V) → one blocker, `issue_type=conflicting_evidence`, `attribute=operating_voltage`, values `24 V DC` and `48 V DC`, status `CONFLICTING` on the stored facts, explanation says both values were kept.
    - A note that mentions only `24V` → no conflict blocker for that ref.
    - Assembly `PAX-COUNT-MOD-E` lifecycle `Prototype` and another counting assembly lifecycle `Released` → one `lifecycle_mismatch` blocker whose explanation names Prototype and Released and does not say Obsolete.
    - ERP material `MAT-20001` status `OBSOLETE` → one `erp_lifecycle` row with that material id. It is not merged into the Prototype assembly row.

    `data_quality_issues(conn)` returns a list of dicts: `issue_type`, `refs`, `detail`, `explanation`.

    Cases:
    - A quarantine row whose raw payload contains quantity `one` and reason mentioning quantity → `invalid_quantity` citing that source row. Do not also insert it into `plm_bom_line`.
    - Two `plm_bom_line` rows with the same normalized variant, assembly, and component → one `duplicate_bom_key` listing both source ids.
    - The same component with raw UOMs `pcs` and `EA` that both normalize to `EA` → one `uom_aliased` issue, not a conflict.
    - Warning counts grouped by type. Types `missing_description` and `empty_supplier` include `mapping_noise: true` inside the summary object `ingestion_warning_summary` (a single dict on the return value, sibling of the issue list — return `{"issues": [...], "ingestion_warning_summary": {...}}`).

    CLI, using the existing argparse style in `app/backend/cli.py`:
    - `review list --entity component [--status PENDING] [--confidence uncertain|likely|strong|weak] [--method METHOD] [--source PLM|ERP] [--relationship identity|functional_similarity|variant_specific] --db PATH`
    - `review decide --entity component --id INT --action accept|reject|redirect [--rationale TEXT] [--redirect-to INT] [--reviewer TEXT] --db PATH`
    - `analyze reuse|candidates|blockers|quality --db PATH` writes `data/processed/already_reused.json`, `reusable_candidates.json`, `blockers.json`, or `data_quality.json` and prints the file path plus the row count.
    - `analyze` commands call `build_canonical_model` before reuse, and call `blockers` / `data_quality_issues` for the other two. They do not ingest files.

    Tests for quality use fixtures. One CLI test may use `tmp_path` and a tiny database; it must not require the real CSV folder.
  </behavior>
