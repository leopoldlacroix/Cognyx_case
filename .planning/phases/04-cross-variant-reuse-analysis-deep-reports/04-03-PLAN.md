<feature>
  <name>Data-quality records and summaries</name>
  <files>app/services/quality.py, tests/test_quality.py</files>
  <behavior>
    Every item in `data_quality_issues(conn)["issues"]` includes `records`: a list of `{source_table, source_id, source_file, source_row}`. `source_file` is `source_file.file_name`. `source_row` is an int. `source_id` is the row id as a string.

    Existing cases, now with records:
    - Quarantine quantity `one` → `invalid_quantity`, and `records` includes that quarantine row's file and `source_row`.
    - Two `plm_bom_line` rows with the same normalized variant, assembly, and component → `duplicate_bom_key`, and `records` has both lines.
    - One component with raw UOMs `pcs` and `units` both normalized to `EA` → `uom_aliased`. `records` may be empty when the query has no line id; `refs` still names the raw UOMs.

    Warning summary:
    - Each `ingestion_warning_summary` entry still has `count`. `missing_description` and `empty_supplier` still have `mapping_noise: true`.
    - Each entry also has `by_source_file`, a dict of file name to count for that warning type. A fixture with two `missing_description` warnings on `bom_export.csv` yields `{"bom_export.csv": 2}`.

    New issue types, appended after the existing ones, sorted by `issue_type` then `detail` within the new types only (do not reorder the existing three relative to each other):
    - `duplicate_reference`: two `source_component` rows share `normalized_reference` and differ in `source_system`. `detail` contains the reference and both systems. `records` names both source-component ids. A single-system reference does not appear. `CTRL-AIR-01` and `MAT-10001` do not appear together unless a fixture sets them to the same normalized string.
    - `conflicting_facts`: one issue per `technical_fact` group of status `CONFLICTING` for the same `entity_type`, `entity_id`, and `attribute`, when at least two distinct `value`s exist. `detail` lists both values. `records` use `source_type` as `source_table` and `source_id` from the fact. Run only after `blockers()` in the test. A single `OBSOLETE` fact is not a conflicting-facts issue.
    - `unresolved_reconciliation`: one issue when any `component_reconciliation` row has status `PENDING` or `REJECTED` and `evidence_json.relationship` is `identity`. `detail` is the count. `records` include each reconciliation id (`source_table` `component_reconciliation`). `ACCEPTED` identity rows do not count. Also return top-level `unresolved_reconciliation_count` equal to that count (0 when there is no issue).
    - `alias_summary`: one informational issue whose `detail` contains `CTRL-AIR01 → CTRL-AIR-01`, read from `config/normalization.json` `reference_aliases`. `records` includes a `plm_bom_line` whose `component_ref_raw` is `CTRL-AIR01` when such a line exists. This issue is not a defect and does not remove the line from reuse.

    Return shape remains `{"issues": [...], "ingestion_warning_summary": {...}, "unresolved_reconciliation_count": int}`.
  </behavior>
  <implementation>
    Join `source_file` for quarantine and `plm_bom_line`. `warnings` has `source_table` and `source_row_id`. For rows written at ingest, `source_row_id` is the CSV `source_row` (header is row 1, first data row is 2), not the table primary key. Group `by_source_file` by joining `warnings.source_table` plus `warnings.source_row_id` to that table's `source_row`, then to `source_file.file_name`. Skip a warning whose table name is not one of the ingested tables. Do not add a column.

    Read reference aliases through `load_normalization_config()` in `app/services/normalization.py`. Do not hardcode the map except in the test expectation.

    Build `conflicting_facts` from `technical_fact`, not by parsing note text again. Build `duplicate_reference` from `source_component` only.

    Do not change blocker explanations. Do not add a web framework.
  </implementation>
</feature>
